## TanStack Start on Cloudflare Workers

Source: <https://developers.cloudflare.com/workers/framework-guides/web-apps/tanstack-start/>

Decision: use `@cloudflare/vite-plugin` with `viteEnvironment: { name: 'ssr' }`,
`tanstackStart()` and `@vitejs/plugin-react`. `wrangler.jsonc` uses
`main: "@tanstack/react-start/server-entry"`. `routeTree.gen.ts` is generated by
the plugin and committed so standalone `tsc` works.

## Cloudflare Durable Objects and WebSockets

Sources:

- <https://developers.cloudflare.com/durable-objects/best-practices/websockets/>
- <https://developers.cloudflare.com/durable-objects/examples/websocket-hibernation-server>

Decisions:

- Gateway validates method/upgrade/`Origin` before calling the DO stub.
- The DO uses `ctx.acceptWebSocket(server)` and `webSocketMessage` /
  `webSocketClose` / `webSocketError`.
- Outgoing provider WebSockets are opened with `fetch` and
  `headers: { Upgrade: 'websocket' }`; the returned `Response.webSocket` is
  accepted with `webSocket.accept()`.
- Hibernation is **not** assumed for active calls: outgoing sockets keep the DO
  alive for up to 15 minutes, and this MVP caps calls at 10 minutes.
- On DO restart with restored client sockets but no live session state, the DO
  sends a typed error and closes. There is no seamless audio recovery.

## Deepgram streaming STT

Sources:

- <https://developers.deepgram.com/docs/streaming>
- <https://developers.deepgram.com/docs/utterance-end>
- <https://developers.deepgram.com/reference/speech-to-text/listen-streaming>

Decision:

```text
https://api.deepgram.com/v1/listen   (Worker fetch upgrade; public endpoint is wss://)
  ?model=nova-3
  &language=en|hi
  &encoding=linear16
  &sample_rate=16000
  &channels=1
  &interim_results=true
  &smart_format=true
  &punctuate=true
  &endpointing=300
  &utterance_end_ms=1000
  &vad_events=true
Authorization: Token <DEEPGRAM_API_KEY>
```

- `nova-3` supports Hindi (`hi`) and English. The worker maps `en-IN` to
  Deepgram `en` because Hindi/English monolingual Nova-3 codes are the verified
  contract; Sarvam still gets `en-IN`/`hi-IN`.
- Deepgram emits `Results` (`is_final`, `speech_final`), `UtteranceEnd` and
  `SpeechStarted`. Turn commits use `speech_final`/`UtteranceEnd` plus a grace
  period.
- A `KeepAlive` control message is sent every 8 seconds.
- No reconnect loop is implemented. An abnormal close fails the call with
  `stt_disconnected`; this is preferable to silently losing audio.

## OpenRouter streaming LLM

Source: <https://openrouter.ai/docs>

Decision: OpenRouter's OpenAI-compatible Chat Completions endpoint with
`stream: true`, `model: openai/gpt-4o-mini`, `max_tokens: 220`,
`temperature: 0.6`.

```text
POST https://openrouter.ai/api/v1/chat/completions
Authorization: Bearer <OPENROUTER_API_KEY>
Content-Type: application/json
```

The server parses SSE incrementally and never waits for the full answer. A
single `AbortController` owns each generation and is aborted on barge-in,
timeout or teardown. Errors map to safe codes (`provider_auth_failed`,
`llm_rate_limited`, `llm_timeout`, `llm_error`).

The model ID is `openai/gpt-4o-mini` (the OpenAI model served through
OpenRouter), confirmed against OpenRouter's model list on 2026-10-29. If the
model is unavailable in your account, change the constant in both
`packages/shared/src/agent-config.ts` and `convex/lib/catalog.ts` and re-run
tests; the sync test enforces agreement.

## Sarvam streaming TTS

Sources:

- <https://docs.sarvam.ai/api-reference/text-to-speech/stream>
- <https://docs.sarvam.ai/api/getting-started/models/bulbul>
- <https://docs.sarvam.ai/api/api-guides-tutorials/text-to-speech/best-practices>

Decision:

```text
https://api.sarvam.ai/text-to-speech/ws   (Worker fetch upgrade; public endpoint is wss://)
  ?model=bulbul:v4-flash
  &send_completion_event=true
Api-Subscription-Key: <SARVAM_API_KEY>
```

Frames:

```json
{"type":"config","data":{
  "speaker":"simran_en_customer",
  "language_code":"en-IN",
  "speech_sample_rate":24000,
  "output_audio_codec":"linear16",
  "pace":1.0
}}
{"type":"text","data":{"text":"..."}}
{"type":"flush"}
```

- Model ID is exactly `bulbul:v4-flash` (hyphen included).
- Voices shipped: `simran_en_customer` (en-IN) and `aparna_hi_customer`
  (hi-IN). Both IDs appear in the current Bulbul v4 Flash docs. Guessed speaker
  IDs are rejected by the shared and Convex validators.
- Audio arrives as JSON `{"type":"audio","data":{"audio":"<base64>"}}`; it is
  decoded to PCM. `PcmNormalizer` strips RIFF/WAVE headers if a deployment
  returns WAV anyway. `linear16` is the requested format; the docs list it as a
  supported output codec for Bulbul v3/v4 Flash.
- Completion events are expected per flushed utterance. If a deployment
  coalesces them, the adapter falls back to a 1.5 s quiet-period completion after
  `finish()`; a 30 s hard timeout still fails the turn.
- A new Sarvam socket is opened per assistant response. This sacrifices
  connection reuse but makes barge-in isolation reliable: closing the socket
  cannot leak old audio into the next response.
- Idle sockets receive `{"type":"ping"}` every 15 seconds.

**Live verification (2026-10-29):** Workers outbound fetch upgrade succeeded,
`linear16` returned raw PCM at 16 kHz for both shipped voices, and each flush
produced exactly one completion event. English and Hindi synthesis both worked
through the real account. The full headless Worker E2E also succeeded for two
turns.

**Important Workers detail:** `fetch` rejects `wss://` URLs in the Workers
runtime. Use `https://` with `Upgrade: websocket`; the public provider endpoint
is still `wss://`. This was found by the live run and is covered by the adapter
default URLs.

## Convex

Sources:

- <https://docs.convex.dev/functions/http-actions>
- <https://docs.convex.dev/functions/runtimes>
- <https://labs.convex.dev/auth/setup>
- <https://docs.convex.dev/testing/convex-test>

Decisions:

- Convex Auth `Password` provider. Every function derives the owner from
  `getAuthUserId` (or an internal query in actions); no owner ID is accepted from
  the client.
- Convex default runtime has Web Crypto, so ticket generation/hashing and HMAC
  verification use `crypto.getRandomValues`/`crypto.subtle` without `"use node"`.
- HTTP actions live in `convex/http.ts`; `auth.addHttpRoutes(http)` installs the
  auth routes.
- M2M auth is HMAC-SHA256 over `timestamp\nnonce\nmethod\npath\nbodyHash`.
  Nonces are stored in `runtimeNonces` and pruned by cron. Replay or stale
  requests return 401.
- Ticket: 32 random bytes (64 hex chars), SHA-256 stored on the call, 60 s TTL,
  cleared on first successful authorization.
- Event ingestion enforces contiguous sequences and deduplicates transcript rows
  by `eventId` and `(callId, turnId)`. `lastEventSeq` is the authoritative cursor.
- A cron reconciler finalizes orphan calls (`session_expired`, `stale_session`).
- `convex-test` runs under the edge-runtime environment. The test builds its
  module map with `import.meta.glob` over the generated `_generated` JS files; no
  live deployment is required for these tests.

## Audio and browser behavior

- Capture AudioWorklet asks for a 16 kHz context; if the browser ignores the
  requested rate, a streaming linear resampler converts to 16 kHz and a
  fixed-frame assembler emits 20 ms frames.
- Playback AudioWorklet asks for 24 kHz; the worklet owns the queue so barge-in
  clears audio on the next quantum. If the output context differs, a streaming
  resampler converts 24 kHz to the context rate.
- The playback `AudioContext` is created synchronously inside the Talk click to
  satisfy autoplay policies. Microphone permission is requested next.
- Worklets are inline JavaScript strings loaded from Blob URLs. This avoids
  bundler-specific `?worker&url` handling for AudioWorklet.
- WAV containers are never enqueued as raw PCM.

## Deliberate limitations

- No SIP/telephony, tools, RAG, recording storage, voice cloning, billing,
  failover, BYOK or active-call reconnect.
- One provider per category. The UI displays only implemented choices.
- STT is monolingual per call (`en` or `hi`), not code-switching.
- Assistant interruption persistence records generated-to-date text, not exact
  audible alignment.
- The Convex `_generated` files in this repository were produced from the
  installed Convex codegen templates because no deployment/credentials were
  available in the build environment. Run `bunx convex dev` (or
  `bunx convex codegen` with a configured deployment) to regenerate them
  normally.
