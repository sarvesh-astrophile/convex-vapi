# Benchmark results

## Preliminary live run — 2026-10-29

**Scope:** one headless 2-turn Worker E2E run, not the required 20-turn /
10-interruption benchmark. There are not enough samples for P50/P95.

**Environment**

- Local WSL2 client, Cloudflare `workerd` via `wrangler dev` (not a deployed edge).
- Convex dev deployment `hardy-gnat-130` (cloud, not local).
- Providers: Deepgram `nova-3` (`en`), OpenRouter `openai/gpt-4o-mini`,
  Sarvam `bulbul:v4-flash`, `simran_en_customer` / `en-IN`.
- Audio: canned 3.09 s English question generated by Sarvam, sent in 20 ms PCM16
  frames at 16 kHz, followed by 1.5 s of silence to endpoint the turn.
- Client: Bun script `bun run e2e:worker`; no browser AudioWorklet playback.
- Machine/network region: WSL2 Linux host, network location not recorded.

**Observed server timings** (`assistant.turn_end.timings`):

| Turn | End of turn → LLM first delta | End of turn → first TTS audio | End of turn → LLM done |
| ---- | ----------------------------: | ----------------------------: | ---------------------: |
| 1    |                       2708 ms |                       5289 ms |                2786 ms |
| 2    |                       2937 ms |                       4920 ms |                2951 ms |

- 2 user finals, 2 assistant turns, 384,000 bytes of PCM16 output
  (8.0 s at 24 kHz mono).
- Deepgram transcribed the canned question exactly.
- Assistant context carried across both turns.
- The <1,000 ms first-audio target was **not met** in this run. Do not present
  this as meeting the performance goal.

**Not measured:** browser first-audible playback latency, barge-in clear time,
P50/P95, 20-turn stability, 10 interruption scenarios, mobile, loudspeaker echo.

**Harness caveat:** `bun run e2e:worker` also prints a “first audio latency”
measured from when it starts sending canned audio. That includes 3.09 s of speech
upload plus 1.5 s of silence, so it is not an end-of-turn metric. Use the server
`turnEndToFirstTtsAudioMs` numbers above for provider-path estimates.

## Provider smoke (same date)

One OpenRouter response, two short Sarvam TTS phrases (English and Hindi), and
one Deepgram STT pass completed successfully in 18,686 ms total wall time. This
proves credentials and contracts, not latency.

## Required full run (still to do)

- At least 20 controlled turns.
- At least 10 interruption scenarios (early/middle/late assistant speech).
- Hindi and English (India) agents.
- Headphones and loudspeakers.
- Same-region and remote-region Durable Object placement.
- Record failures as well as successes.
